# M3：旧版内容与 BaseLib 玩法恢复验收

更新日期：2026-10-21。本轮保留 Next 独立战斗接口，按 Classic 源码和历史玩法恢复内容与尖塔原生界面。前置为 BaseLib v3.4.7；本机适配 Terraria 1.4.5.8、尖塔 v0.111.0。安装名为“泰拉瑞亚 × 杀戮尖塔 2”，内部 ID 保持 `SpireTerrariaNextProbe`。

## 回退原因与修复

接口迁移后的目录、原生绘制和宿主接线没有完整覆盖旧版行为，造成内容缺失、武器不可见、事件重复和战斗清理遗漏。本轮逐项补回，并以实际游戏流程和本机原生绘制结果验收。

| 回退 | 本轮修复 |
| --- | --- |
| 剑、弓、法术书等武器不可见或没有动作 | 使用原生人物绘制层、手持位置及使用动作；原生服务端标记会跳过动作并返回空物品裁剪帧，现仅在原生表现计算／绘制期间切换并在 finally 恢复；验证三类武器真实非零纹理帧和连续切换 |
| 怪物消失、瞬移、越界后卡关 | 修正原生动画帧尺寸；取消越界时重建 NPC，保留生命和 AI 状态，只在边界／掉落时回收；固定夜间，防止夜间怪物和 Boss 白天离场 |

## 当日补充：战斗自然获胜自动使用原生 win

原先自然胜利只对当前尖塔敌人快照调用 `CreatureCmd.Kill(..., force:true)`。`InfestedPower` 会在死亡后生成四只寄生怪，`StockPower` 会在死亡后补下一只机器人；快照击杀没有消除这些后续敌人及阻止结算的能力，导致泰拉战斗结束后无法领奖。

现于 `HostIntegration.Complete` 保存真实泰拉战斗进度、清理实时战斗层并恢复尖塔处理后，直接调用 `WinConsoleCmd.Process(player, Array.Empty<string>())`，检查返回结果并等待其 task 完成。原生 win 会先清除敌人能力，再击杀并检查胜利。胜利分支不再重复额外调用 CheckWinCondition；失败分支保留原流程。真实泰拉 Boss 来源在命令前保存，内部命令不会进入手动 win 的中断保存分支。

最终 `Test-Spire.ps1 -VictoryRegression -TimeoutSeconds 240` 在实际游戏中耗时 52.213 秒通过，启动器退出码 0。使用真实地图连续三个房间，只在隔离内存测试中替换为指定原生遭遇；为缩短战斗，将测试角色的起始武器设为 +20 并在战前恢复生命，未改产品数值。每场仍由原生泰拉模拟实际击败敌人，测试没有直接发胜利指令。

| 原生遭遇 | 实际死亡能力 | 结算与后续 |
| --- | --- | --- |
| PhrogParasiteElite | InfestedPower ×4 | 自动原生 win 完成，残留敌人 0；装备领取、返回地图与 worker 回收通过，保留 KingSlime 掉落来源 |

结束后输入正常、无战斗层与残留进程，Mod 开关已恢复；418 个真实存档相关文件与本次测试前哈希一致。安装宿主、清单和 worker 与最终构建一致。完整证据保存在 `.local/win-settlement/`，最终报告为 `victory-settlement-report.json`、`launcher-report.json`、`integrity.json`，另有三场逐房间截图和日志。此补丁后的安装哈希以本目录的 integrity.json 为准；之前恢复基线的报告保留。
