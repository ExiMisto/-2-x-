# 泰拉远征开发路线

## 产品目标

尖塔及 BaseLib 负责选角、地图、真实装备牌组、饰品／药水栏和房间交互；自有独立接口连接本机泰拉人物、武器、敌人、弹幕与地形。保留四职业、三武器槽、分幕装备、单件加算强化、材料锻造与免费词条。

“超越”通过可复核的能力判断，不以代码行数或功能承诺判断：

| 方面 | 现有融合版限制 | 新核心验收目标 |
| --- | --- | --- |
| 桥接 | 依赖上游工作进程和协议 | 自有协议、加载器、调度与渲染路径；逐项记录来源 |
| 存档 | 不保存远征 | 节点间可退出续玩；原子写入、版本迁移；失败不损坏原版进度 |
| 声音 | 原生声音未转发 | 武器、敌人、受击、环境声音可听；暂停、切房和音量正确 |
| 场地 | 单一森林竞技场 | 按幕与节点选择生态场景；固定种子可复现，出生点和碰撞安全 |
| 战斗 | 样本通过，未完整通关 | 四职业各完成三幕；记录耗时、受伤、武器使用与胜率，再做平衡 |
| 稳定性 | 缺少进程故障恢复流程 | 加载失败可回退；超时能取消；工作进程崩溃不拖死宿主 |
| 输入 | 战斗隔离已有样本 | 游戏失焦、弹窗、地图覆盖和退出均恢复按键与鼠标状态 |
| 安装 | 本机固定版本与目录 | 前置版本检测、可配置路径、从本机读取资源，给出可操作错误 |

## 实施次序

1. **M0 原生访问与通信**：自有有界控制帧协议、随机会话凭证、握手与协议版本检查、游戏版本检测、API 和 ItemID 读取、真实装备属性查询、超时与受控退出。客户端只接受配对响应，拒绝错误序号与超长帧。
2. **M1 可见战斗闭环**：自有 XNA / Terraria 启动、真实人物和一只怪的场地、固定时间步、输入、帧回读与暂停；宿主显示一场实际战斗并按真实结果结束。测量帧耗时和传输量。
3. **M2 尖塔接入**：独立接口已完成地图、实际战斗、奖励和取消恢复的首个闭环；历史记录保持独立。
4. **M3 恢复完整玩法基线**：接回 BaseLib 四职业、273 个物品模型、原生装备牌组和库存；恢复旧版起装与操作。原生选角至下一战斗的房间旅程已通过，后续验收完整退出续玩与故障回退。
5. **M4 表现与平衡**：原生音效、生态场地、Boss 专用布局；按战斗遥测调整装备与敌人，而非无限叠加角色倍率。

M0、M1 与 M2 首个接入样本已有通过记录。M3 现有 273 项目录的 2307 项模型检查、333 个本机物品分类检查及 13 项原生消耗品检查通过；本轮恢复 BaseLib 后的实际界面旅程也已通过。旧源码仅供对照，运行时继续使用新 worker；完整退出续玩和整局平衡尚待验证。详见 [M3-VALIDATION](M3-VALIDATION.md)。

控制消息与画面传输分开设计：管道消息有 1 MiB 上限，图像由双缓冲共享内存传输。M1 当前输出 640×360 BGRA32，分别验证了合成帧传输和真实战斗画面；后续以完整场景实测决定最终尺寸，不预先承诺无损 1080p / 60fps。

## 开发约束

- 新核心不链接旧 Mod DLL、旧工作进程或上游协议文件。
- 只读取本地游戏程序与素材；不在这里打包原版程序集或提取素材。
- 不因未使用的原项目许可要求额外授权；只有实际引入的第三方代码、资源或发布平台规则需要逐项处理。
- 默认不触碰玩家角色、世界和宿主进度；验证使用项目下 `.local/`。
