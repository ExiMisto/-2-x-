# 原生伤害显示

更新日期：2026-10-21。目标运行时为 Terraria 1.4.5.8，宿主为尖塔 v0.111.0 和 BaseLib v3.4.7。

## 实现

原生 NPC 命中、玩家受伤与持续伤害本来已产生 `Main.combatText`，独立战斗循环也已调用 `CombatText.UpdateCombatText`，但渲染层没有画出这些文字。本轮补上该绘制层，直接使用本机 `Combat_Text`、`Combat_Crit` 字体及原生条目的文本、位置、颜色、透明度、旋转和缩放。文字有黑色描边，显示在人物和血条之上。

显示不再计算伤害，也不通过生命差生成新的数字；伤害、防御、暴击与持续伤害仍由原生战斗结算。渲染不推进文字生命周期。切房间沿用原生数组清理，渲染器释放时恢复先前的字体绑定。字体只从本机游戏加载，不打包进 Mod。

工作进程诊断增加 `combatText.visible`、`combatText.peak` 和 `combatText.drawTotal`。游戏自测在同一串行战斗循环中读取这些字段，记录实际画面出现数字的证据；正式游玩不增加诊断请求。

## 针对性验证

运行 `tools/Test-NativeCombatText.ps1`，会构建独立 x86 探针，以真实泰拉模拟和渲染目标验证以下行为，共 24 项检查：

| 场景 | 实测 |
| --- | --- |
| 普通命中 | 输入伤害 45，经敌人 10 防御后实际扣血 40，原生数字为 40 |
| 暴击 | 同样输入下实际扣血 80，数字为 80，使用更大的原生暴击字体 |
| 玩家受伤 | 实际扣血 37，数字为 37，保持原生受伤颜色 |
| 灼烧持续伤害 | 真实燃烧减益产生 `dot` 条目及数字 1 |
| 画面可见性 | 在同一静止世界中，仅关闭文字后分别减少 312、475、243、75 个可见字形像素 |
| 生命周期 | 文字飘动并自动消失，重复绘制不减少生命周期 |
| 房间与资源清理 | 离开房间后无文字残留，下个房间从空文字池开始；字体静态绑定恢复 |

证据在 `.local/damage-feedback/native/`：`combat-text-verification.json` 和四张原生渲染图片。测试只在内存中构造敌人和伤害，不加载真实玩家或世界。

本轮也验证剑、弓和法术书连续切换与原生动作，9 项检查通过，证据在 `.local/damage-feedback/weapon-regression/`。饰品的 49 个原生短样本及具体说明见 [饰品说明与核验](ACCESSORY-DESCRIPTIONS.md)。短样本不能替代全部装备机制和整局平衡验收。

## 尖塔内最终验收

最终安装版本执行 `Test-Spire.ps1 -Adventure -TimeoutSeconds 240` 通过，游戏内测试 54.395 秒，启动器总计 65.870 秒、退出码 0。实际走通四职业选角检查、地图、自然战斗胜利、装备奖励、火堆、商店、宝箱、事件／远古之民、下一战斗与地图暂停。

- 实际尖塔战斗画面出现伤害跳字，报告 `nativeCombatTextVisibleInGame = true`，有原生绘制诊断及 `combat-damage.png`。
- 48 件饰品逐一核验原生标题、说明与 `CanonicalModel`；显示集合保留 BaseLib 正常的模组来源脚注。商店、宝箱、战斗栏使用真实原生回调创建悬浮框，正文与目录一致且完整位于 viewport 内。
- 初次画面复核发现战斗层遮住原生提示框。本轮在战斗期间将原生提示容器临时提升至 111 层，位于战斗层 110 之上；保留原生定位、内容和交互，退出后恢复父节点、顺序及处理模式。
- 最终战斗提示截图经目视确认完整可见；暂停同一场景的前后图像中，说明区域 85,500 像素有 75,790 像素变化，其中 10,254 个为亮色文字像素。测试同时断言提示位于更高画布层，避免只检查节点的 Visible 状态而漏掉遮挡。`nativeTooltipLayerRestored = true`。
- 真实药水栏消费、胜利后原生 win 结算、战斗层关闭和输入恢复继续通过。本轮没有重做三类分裂／补怪遭遇专项，它们先前的通过证据仍在 `.local/win-settlement/`。

最终证据位于 `.local/damage-feedback/spire/`，包括报告、日志、跳字截图、三种场所的饰品提示截图，以及战斗提示出现前的对照图。`integrity.json` 核验安装 DLL、清单及 worker 均与最终构建一致；418 个真实存档相关文件变化 0、缺失 0，Mod 开关已恢复，游戏和 worker 均无残留进程。日志仍有禁用旧 Mod 的扫描提示及 Godot 退出资源诊断，不计为本轮新增功能已消除所有引擎警告。
