# 控制协议 v1

此协议由新核心单独设计。当前采用同一台 Windows 上的命名管道，控制请求串行处理。

## 帧

所有整数为 little endian。固定头 16 字节，后接正文：

| 字段 | 字节 | 内容 |
| --- | ---: | --- |
| Magic | 4 | `0x32585453` |
| 协议版本 | 2 | `1` |
| 操作 | 1 | 见下表 |
| 标记 | 1 | bit0 为响应，bit1 为错误；其他位必须为 0 |
| 请求序号 | 4 | 有符号 int，必须为正且递增 |
| 正文长度 | 4 | 有符号 int，范围 0–1,048,576 |

正文采用 .NET BinaryReader / BinaryWriter 的原始整数和 UTF-8 长度前缀字符串编码。非法帧、方向或序号关闭连接；已认证会话中的业务错误返回错误响应，正文依次为错误类型和说明。

## 操作

| 编号 | 操作 | 请求 | 正常响应 |
| ---: | --- | --- | --- |
| 1 | Hello | 会话凭证字符串 | 工作进程标识、ushort 协议版本、int 指针位数 |
| 2 | Inspect | 空 | 游戏程序集名、程序集版本、文件版本、指针位数，随后六组类型名与方法数 |
| 3 | ItemIds | int 数量及符号字符串，最多 128 条 | int 数量，随后符号与原生 int ID |
| 4 | Ping | 空 | `pong` |
| 5 | Shutdown | 空 | `bye`，随后工作进程退出 |
| 6 | ItemStats | 一个原生物品符号 | 符号、ID、damage、defense、useTime、useAnimation、mana、rare，数值均为 int |
| 7 | BattleStart | int 种子、武器符号、NPC 符号 | 共享帧会话名、int 宽、int 高，随后 BattleState |
| 8 | BattleStep | int 步数、byte 输入、float 世界瞄准 X/Y | BattleState |
| 9 | BattleEnd | 空 | `ended`，关闭当前画面通道并释放图形资源 |
| 10 | AdventureStart | BattleConfiguration | 共享帧会话名、int 宽高，随后 AdvancedBattleState |
| 11 | AdventureStep | int 步数、byte 输入、float 瞄准 X/Y、int 武器索引、可选 int 消耗品索引 | AdvancedBattleState |
| 12 | ArenaDiagnostics | 空；需要场地已启动 | int 条目数，随后若干键／值字符串 |
| 13 | ItemIcons | int 数量及物品符号字符串，每批 1～12 个 | int 数量，随后符号、int 宽高、连续 RGBA32 像素 |
| 14 | SceneArt | int 职业（战士 0、射手 1、法师 2、召唤师 3） | int 宽高，随后连续 RGBA32 像素 |

Hello 必须为首个请求；会话凭证为随机 32 字节的十六进制字符串，进程通过重定向标准输入接收，命令行不携带凭证。客户端只接受与请求操作和序号匹配的响应。

尖塔宿主等待连接 6 秒、响应 8 秒；worker 连接等待 5 秒，空闲读取上限 15 秒。暂停期间宿主发送 Ping 保持会话。回收时先关闭管道并等待，超时再终止自己的子进程。

此信道仅用于控制与少量数据。图像通过独立共享内存传输，详见 [FRAME-TRANSPORT.md](FRAME-TRANSPORT.md)；音频协议尚未实现。

## M1 战斗消息

`BattleStart` 当前接受 `EnchantedSword`、`WoodenSword` 或 `WaterBolt`，NPC 为 `BlueSlime`。这是已验证的有限内容入口，不代表所有原版武器和 Boss 已兼容。重复开始需要先结束当前场地。每次开始生成新的共享帧会话名，仅通过已认证的控制管道返回。

`BattleStep` 每步对应一次原生角色、NPC 和弹体更新；步数为 1–120。输入位依次为左移 `1`、右移 `2`、跳跃 `4`、使用武器 `8`。世界瞄准坐标必须是有限数值，且绝对值不超出世界像素范围。未收到步进请求时模拟暂停，画面读取本身不会推进时间。无效输入在更新前拒绝；原生更新异常后应结束场地并重开。

`BattleState` 按顺序写入：

| 类型 | 内容 |
| --- | --- |
| int × 3 | 已运行 tick、玩家当前生命、玩家最大生命 |
| float × 2、bool | 玩家 X/Y、玩家死亡标志 |
| int × 2 | 目标 NPC 当前生命、目标 NPC 最大生命 |
| float × 2、bool | 目标 NPC X/Y、目标 NPC 存活标志 |
| int、long | 活动弹体数、最新共享画面帧号 |

当前场地为 512×256 地块，地表第 168 行，预览为 640×360 BGRA32。宿主通过生命值和原生死亡标志判断结果；帧号用于配对控制状态与画面，不能从画面中的血条推断结果。

## 远征配置与状态

`BattleConfiguration` 按顺序写入：

1. int 种子、int 幕数；房间类型、场景键、Boss 符号三个字符串；int 当前／最大生命。
2. int 武器数量；每把依次为符号字符串、int 强化等级、词条字符串。
3. 防具字符串数组、int 整套强化等级、词条字符串；饰品字符串数组。
4. int 总敌人数、int 同时在场上限；消耗品字符串数组。

字符串数组均为 int 数量及逐项字符串。武器 1～3 把，防具最多 3 部位，饰品与消耗品各最多 64 项，幕数 1～3。等级范围 0～1000。配置只传原生符号和数值，不传尖塔模型或游戏程序集。

`AdventureStep` 保留原有四个输入位，并增加投掷 `16`、快捷药水 `32`、下穿平台 `64`。宿主 H / J 选择治疗／魔力药水后传明确的消耗品索引；1～6 属于宿主快捷栏操作。消耗品索引为本场配置数组中的位置，`-1` 表示本次未指定；为兼容先前客户端，正文没有该附加 int 时也按 `-1` 处理。

`AdvancedBattleState` 先写入上表 `BattleState`，再依次追加：

| 类型 | 内容 |
| --- | --- |
| int × 5 | 在场存活数、剩余总数、总波数、当前波数、越界回收次数 |
| float × 5 | 摄像机 X/Y、场地左右边界、地面 Y |
| int、string | 选中武器索引、场景标题 |
| int、int[] | 已消耗索引数量、对应索引列表 |
| int × 4 | 当前魔力、最大魔力、治疗药水冷却、正在使用的消耗品索引 |

末尾四项是新增尾部数据，读取器兼容没有此尾部的旧状态包；本仓库宿主和 worker 应配套构建。只有原生更新确认实际使用后才加入已消耗索引，宿主据此移除真实药水模型。切房后使用新配置，不沿用上场数组索引。

`ItemIcons` 可以在没有战场时读取，用于菜单预热；不会启动战斗或推进模拟。每个符号最长 128 字符，每边最大 128 像素，12 个图标仍受 1 MiB 正文上限约束。RGBA 数据来自本机纹理，解除预乘透明度后传给 Godot；只在内存缓存。地图画面仍走独立共享帧通道。

`SceneArt` 同样不需要战场，返回 640×360 的选角背景。正文为宽、高两个 int 和 921600 字节 straight RGBA，没有附加长度或职业回显。worker 用本机森林背景、地块、人物与职业武器合成，宿主仅在内存缓存；不写入或打包原版素材。非法职业值及尾随数据均拒绝。
